# 03. Core Value

> 問い: 機能説明を超えた一文で、Floteは何か

## 仮確定 (2026-04-19 対話)

**Flote = 整理を要求しないメモアプリ**

### キャッチコピー暫定 (2026-04-19 対話)

> **書き続けろ、整理は必要ではない。**

- 構造: 行動命令 (書き続けろ) が先、既存常識の否定 (整理は必要ではない) が後
- 意図: 既存メモアプリが暗黙に要求する「後で整理しろ」を拒絶し、ユーザーに許可を与える
- **暫定扱いの理由**: ターゲットの人間像 (職種 / 認知特性 / ライフスタイル) が未確定のため、最終文言はターゲット確定後に再調整が必要
- 既存候補との関係: LP の「走り書きが、勝手に整理される」(プロダクトの提供価値) と、このコピー (ユーザーへの呼びかけ) は役割が異なる。両立可能

- 既存メモアプリ (Notion / Obsidian / Bear / Apple Notes) は**「整理できる人」**を前提に設計されている
- 使いこなし前提のUXなので、一般人は使いこなせない。「機能として使用している人が少ない」(新井)
- Flote は**「整理できない状態」「整理したくない気力」**を受け入れ、**AIが後から意味を回復する**
- 「走り書きのまま、勝手に整理される」(2026-04-14 表現) の**実体験による裏付け**が今回の対話で得られた

### なぜこれが差別化になるか

| 競合 | 前提とする人 |
|------|------------|
| Notion / Obsidian / Bear | 整理できる人、使いこなし前提 |
| Apple Notes / Stickies | 整理しない人 (でも整理機能は提供しない、ただ書くだけ) |
| **Flote** | **整理できない人 (Flote が代わりに整理する)** |

→ 他の全員がカバーしていない象限を独占可能

## 既存の叩き台 (2026-04-14 スナップショット)

**「走り書きのまま、勝手に整理される」**

- 論理: メモ本来の「雑に書く」と「後で整理する必要性」の矛盾を解消
- ポジション: Apple Notesは同期を解決したが整理は未解決、そこに刺す

> ※ これは現状「機能説明」に近い。本来のコアバリューは「Floteを使う人が得る感情/状態変化」を表現すべき。
> 例: Bearの「書くことが気持ちよくなる」/ Notionの「すべてが繋がる」/ Obsidianの「知が育つ」

## 検討すべき問い

- 「整理される」結果、ユーザーは**どんな気持ちに**なるのか (安心? 集中? 軽さ?)
- 「整理される」結果、ユーザーは**どんな行動**ができるようになるのか (新しい判断? 決断? 創造?)
- 一行キャッチコピー案 (対話で複数出す)
